## Blocker

**B1. The GPU timer reports 2–3× too little GPU time, so auto tier, the ladder, the F3 overlay and `?bench` all get wrong numbers on WebGPU.**
`fl-wt-render/apps/client/src/render/timing.ts:14-16,44`
```ts
this.last = ms / Math.max(1, frames);
```
- **What goes wrong:**
  - In three r186, `resolveTimestampsAsync` returns the GPU time of the *last frame* only, not a sum since the previous call. The source says so ("Return the total duration of the last frame"); timestamps are tagged with a per-frame number that ticks every animation frame.
  - The timer only re-resolves every 2–3 frames, so dividing by `frames` shrinks every sample by 2–3×. The WebGL2 timer behaves the same way.
  - On an M1 Air the probe sees roughly 4 ms at Medium and moves up to High or Ultra.
  - The ladder then never steps down: it needs the reported time above 1.15× the target, which means a real time of about 30 ms or more. It also steps resolution up on fake headroom.
- **Fix:** set `this.last = ms` and drop the frame counting. Add a test with a fake renderer whose resolve returns per-frame values.

**B2. Merging main needs hand resolution beyond the textual conflicts.**
Conflicts: `fl-wt-render/apps/client/src/game/Game.ts` (11 hunks) and `fl-wt-render/packages/shared/src/index.ts` (keep both exports; no names collide). Picking either side wholesale breaks something:
1. **Double rendering.** Main's `frame()` renders whenever `!running || travelling`, and main's `resume()` sets `running = true` before calling `enterBody`.
   - The lane's probe, warm-up, `applyGraphics` and `reprobe` render on their own frame loop. Merged, there would be two renders per frame, so the probe measures double GPU time and picks a lower tier.
   - `frame()` would also change the scene while warm-up has forced objects visible and props into both detail levels.
   - Fix: add a `warming` flag set around `runProbe`/`warmup`, and have `frame()` return without rendering while it is set.
2. **`reprobe()` and `applyGraphics()` always set `running = true` at the end** (lane `Game.ts:225,247`). After main's logged-out or notice screens (which set `running = false`), a re-probe from F3 would restart player input and movement under the menu. Fix: save the previous `running` value and restore it.
3. **Offline/bench path.** Keep the lane's `OFFLINE` branch, but in it skip `combat.attach()`, `onLeaveRoom`, the `requestTravel` portal checks, and main's `characterPick`/`pickDisplayName`. Call `planet.update` with `focus`; give portals and combat `this.player.pos`; keep `this.combat.aiming()`. Keep `padDirs` in the import (lane's `spawnPoint` uses it).
4. **Shaders compiling mid-combat.** Main's combat `Effects` (`render/effects.ts`) and `PilesView` create meshes after warm-up, so their shaders compile on first shot, explosion or pile. Fix: add a warm-up hook that spawns one of each, or keep hidden prototypes in the scene (warm-up already shows hidden objects).
5. **Menu grade never applies.** Main's `Menu` never calls the lane's `Game.setMenuMode`.
6. Keep the lane's `a.root.visible = settings.on.chars` and `updateAvatarDetail` in the remote-avatar block.

## Should-fix

**S1. An empty probe sample set picks High and saves it.**
`fl-wt-render/apps/client/src/render/probe.ts:52-54,67`
- **What goes wrong:** `percentile([])` returns 0, and 0 is less than 6, so the tier is "high". This happens if the tab is hidden or the browser throttles frames in the first ~3 frames of `measure()`: one huge frame ends the loop and `slice(3)` leaves nothing. The result is saved as `autoTier`.
- **Fix:** require at least 30 frame samples and `document.visibilityState === "visible"`. Otherwise return Medium without saving.

**S2. The saved auto tier never expires, and ladder tier drops are never saved.**
`fl-wt-render/apps/client/src/render/renderer.ts:107,175-183,229-237`, `fl-wt-render/apps/client/src/render/quality.ts:121-150`
- **What goes wrong:**
  - After a Chrome GPU-process crash, Chrome renders in software (SwiftShader). The probe then saves Low, and the user stays on Low forever.
  - A result probed on WebGL2 is reused on WebGPU.
  - Ladder floor drops are not saved, so every session walks down the ladder again.
- **Fix:** save `{autoTier, backend, gpuName}` and re-probe when either differs. When a drop happens in auto mode, save the lower tier with `setProbedTier(lower)`.

**S3. A ladder tier drop freezes the game.**
`fl-wt-render/apps/client/src/render/renderer.ts:229-237`
- **What goes wrong:** `onFloor` calls `apply()` in the middle of play with no warm-up. That rebuilds post-processing and new terrain/water variants. Shadows switching from shadow map to blob changes `light.castShadow`, which is part of the lighting shader key, so every lit material is rebuilt synchronously. Expect a freeze of hundreds of milliseconds to seconds on Metal.
- **Fix:** expose an `onTierDrop` callback and route it through `Game.applyGraphics` (loading overlay plus warm-up).

**S4. Without a GPU timer, the ladder oscillates.**
`fl-wt-render/apps/client/src/render/timing.ts:116-118,136`
- **What goes wrong:** `isFast = rafP50 < 17.2` is true whenever a 60 Hz display holds vsync. After any down-step, the ladder steps up every ~38 s and then spends 4–8 s slow before stepping down again. This hits WebGL2 and Safari.
- **Fix:** disallow up-steps without a GPU timer, or double `noUpUntil` each time an up-step is followed by a down-step.

**S5. `warmup()` has no try/finally.**
`fl-wt-render/apps/client/src/render/warmup.ts:81-118`
- **What goes wrong:** if `ctx.render()` throws (for example a shader-graph error), `forceAll` stays on. Both prop detail levels keep drawing, every prop within draw range keeps casting shadows, frustum culling stays off scene-wide, and hidden objects stay visible.
- **Fix:** wrap the frames in `try { … } finally { restore; forceAll(false) }`.

**S6. GPU memory leaks on every post-processing rebuild.**
`fl-wt-render/apps/client/src/render/post.ts:90,118`
- **What goes wrong:** `fxaa(out)` and `traa(color)` internally create an intermediate render target (via `convertToTexture`) that is never disposed, and three's `RTTNode` has no `dispose`. Each rebuild leaks a full-resolution half-float render target (~12 MB at 1.5 MP). Rebuilds happen on every tier or feature change, and 2–3 times during the startup probe.
- **Fix:** call `convertToTexture` explicitly, push `{dispose: () => rt.renderTarget.dispose()}`, and also push the FXAA/TRAA nodes into `disposables`.

**S7. Every planet change rebuilds every lit material.**
`fl-wt-render/apps/client/src/world/Planet.ts:118,120` (with `fl-wt-render/apps/client/src/render/atmosphere.ts:181-187` and `fl-wt-render/apps/client/src/render/grass.ts:180,361`)
- **What goes wrong:** three r186's lighting cache key includes each `light.id`. Each `Planet` creates a new `SunRig` (new sun and hemisphere lights) and a new grass material, so all lit materials are rebuilt on every travel. That contradicts the comment at `Planet.ts:41-42` and lengthens travel loading.
- **Fix:** create `SunRig` and the grass material once (module or `Game` scope) and re-apply the planet's look on travel.

**S8. Ladder decisions use stale GPU samples.**
`fl-wt-render/apps/client/src/render/renderer.ts:221`, `fl-wt-render/apps/client/src/render/timing.ts:55-63`
- **What goes wrong:** `gpu.p50()` covers the last 240 samples, about 12 s. The next decision after a step therefore mostly uses samples from the old resolution.
- **Fix:** collect GPU samples per 2 s window, and drain them in `ladder.onChange`.

## Nit

**GPU and rendering**
- **Fragment index truncation** (`fl-wt-render/apps/client/src/render/skyPlanets.ts:45`): `int(attribute("pIdx"))` reads an interpolated float, so 2.9999 can become 2 and pick the wrong planet's colours. Use `int(attr.add(0.5))`.
- **Old particle buffers not freed** (`fl-wt-render/apps/client/src/render/particles.ts:117-125`): on resize the old attributes wait for garbage collection. The comment says they are "released", but they aren't.
- **No device-lost handling** (`fl-wt-render/apps/client/src/render/renderer.ts`): no `renderer.onDeviceLost`, so after a GPU loss (common after macOS sleep) the canvas stays black. Show a reload prompt.
- **Unclamped pixel ratio** (`fl-wt-render/apps/client/src/render/renderer.ts:204-207`): `?scale=2` × `dprCap` 2 gives a pixel ratio of 4. Clamp the final value to `devicePixelRatio`.
- **Warm-up restore overrides visibility** (`fl-wt-render/apps/client/src/render/warmup.ts:87-90`): restoring `visible = false` overrides visibility set during warm-up. A grass cell re-acquired and filled during warm-up stays hidden until it is released.

**Terrain worker**
- **AO seams at cube-face edges** (`fl-wt-render/apps/client/src/world/terrain.worker.ts:99-104`): the clamped neighbour samples differ on each side of a face edge, so baked AO shows lines along the 12 cube edges.
- **Baked sun missing after a drop to Low** (`fl-wt-render/apps/client/src/world/Planet.ts:280`): `bakeSun` is fixed when a chunk is requested, so chunks already loaded before a drop to Low have no baked sun until they reload.

**Per-frame allocations (minor GC)**
- `fl-wt-render/apps/client/src/render/props.ts:170-177` creates two `subarray` views per prop on each refresh.
- `fl-wt-render/apps/client/src/world/Planet.ts:191` (Vector3), `fl-wt-render/apps/client/src/render/atmosphere.ts:243-263` (5 Vector3), lane `Game.ts:318-330` (blob array and closure) and `bench.crowdViews()` allocate every frame.
- `Planet.ts:204,266` builds string keys for all chunks on every streaming tick; precompute them.
- The ladder sorts 240 samples every frame; compute the median only at window end.

**Draw calls**
- On Portus at Medium, 4-quad grass cells are about 9.4 m, giving ~100 cells in range (~40–50 draws after frustum culling). That is the largest draw-call consumer. Use 8-quad cells when quads are under 3 m.

**Code and robustness**
- **Reset can fail** (lane `Game.ts:67-70`): `localStorage.removeItem` throws when storage is disabled, which kills the reset button.
- **Re-probe** (lane `Game.ts:236-249`): it applies settings twice (two post rebuilds). If it throws, it leaves `auto = true` while a pinned tier is still saved.
- **`destruct` toggle never read** (`fl-wt-render/apps/client/src/render/quality.ts:40`).
- **Bench argument spread** (`fl-wt-render/apps/client/src/render/bench.ts:267-272`): `Math.max(...frames)` can exceed Safari's argument limit (~65k) on long runs at high refresh rates.

**Spec**
- SPEC §7.3 asks for "a fixed Portus view". The lane probes from the spawn camera, and after the merge main starts on the last body (`fl.body`).

**Other**
- **Prop placement (shared code):**
  - Each cube face has its own placement grid, so props can double up within one cell across a face seam (`fl-wt-render/packages/shared/src/planet/props.ts:205-213`).
  - The order of `PROP_STYLES` is effectively part of the client/server contract; consider a version constant.
- **Portal leak on main:** `Portals.dispose()` leaks geometry, materials and the label textures on every travel (main's code).

**Determinism (focus 3): no bugs found.**
- Shared props, terrain, noise and RNG use only arithmetic, `sqrt`, `floor` and `imul`; none of the math functions whose results can differ between JS engines.
- Each prop belongs to the chunk containing its jittered point, and tests cover chunk-boundary independence.
- Main's portal spots sit inside the prop clearings (8.5 m < 14 m; 17 m < 48 m on the Portus plaza), so no prop blocks a portal.
- The server doesn't use `chunkProps` yet on either branch.
